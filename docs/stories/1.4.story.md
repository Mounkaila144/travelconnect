## Story

**En tant qu'** utilisateur connecté,
**Je veux** avoir un profil avec mes informations de base,
**Afin que** les autres utilisateurs puissent me connaître et me faire confiance.

---

## Acceptance Criteria

1. À la première connexion, l'utilisateur est dirigé vers un écran de complétion de profil
2. Le profil contient : nom d'affichage, photo, bio courte (max 150 caractères), pays
3. L'utilisateur peut choisir son type : "Voyageur" ou "Local Supporter"
4. Un badge visuel distinct indique le type d'utilisateur (Voyageur/Local)
5. La photo de profil peut être uploadée depuis la galerie ou l'appareil photo
6. Les photos sont redimensionnées à 400x400px avant upload
7. L'écran "Mon profil" affiche toutes les informations avec le score de confiance (initialisé à 0)
8. L'endpoint GET `/api/user/profile` retourne les données du profil connecté
9. L'endpoint PUT `/api/user/profile` permet de modifier les informations

### Profile Management Architecture

[Source: architecture/5-spécification-api-rest.md#5.3.3]

**Profile Endpoints:**

**GET /api/user/profile**

Returns current authenticated user's profile.

**Response (200 OK):**
```json
{
  "data": {
    "id": 1,
    "email": "user@example.com",
    "name": "Tanaka Yuki",
    "avatar_url": "https://storage.ovh.net/avatars/1_1706700000.jpg",
    "bio": "Voyageur passionné",
    "country_code": "JP",
    "user_type": "traveler",
    "trust_score": 4.2,
    "is_new": false,
    "questions_count": 5,
    "answers_count": 12
  }
}
```

**PUT /api/user/profile**

Updates authenticated user's profile information.

**Request Body:**
```json
{
  "name": "Nouveau Nom",
  "bio": "Nouvelle bio",
  "country_code": "JP",
  "user_type": "local_supporter"
}
```

**Validation Rules:**
- `name`: required, string, min:2, max:100
- `bio`: nullable, string, max:150
- `country_code`: required, string, size:2, in:valid ISO codes
- `user_type`: required, in:traveler,local_supporter

**Response (200 OK):** Updated user object

---

**POST /api/user/avatar**

Uploads user profile photo.

**Request:**
- Content-Type: multipart/form-data
- Body: `avatar` (file, image/jpeg or image/png, max 5MB)

**Response (200 OK):**
```json
{
  "avatar_url": "https://storage.ovh.net/avatars/1_1706700000.jpg"
}
```

### Database Schema

[Source: architecture/9-schéma-de-base-de-données.md]

**Users Table Fields for Profile:**
- `id` - BIGINT UNSIGNED PRIMARY KEY
- `email` - VARCHAR(255) UNIQUE NOT NULL
- `name` - VARCHAR(100) NOT NULL (editable)
- `avatar_url` - VARCHAR(500) NULL (editable)
- `bio` - VARCHAR(150) NULL (editable)
- `country_code` - CHAR(2) NOT NULL DEFAULT 'JP' (editable)
- `user_type` - ENUM('traveler', 'local_supporter') NOT NULL DEFAULT 'traveler' (editable)
- `trust_score` - DECIMAL(3,2) NOT NULL DEFAULT 0.00 (computed)
- `is_new` - BOOLEAN NOT NULL DEFAULT TRUE (set to false after first profile update)
- `provider` - ENUM('google', 'apple') NOT NULL (not editable)
- `provider_id` - VARCHAR(255) NOT NULL (not editable)
- `created_at`, `updated_at` - TIMESTAMP

**Computed Fields (not in database):**
- `questions_count` - COUNT of questions by user
- `answers_count` - COUNT of answers by user

**Trust Score Calculation:**
[Source: Epic 3 - Story 3.4]
- Formula: `average_rating × log(answers_count + 1)`
- Range: 0.00 to 5.00
- Displayed with 1 decimal place
- New users show "Nouveau" instead of 0.00

### OVH Object Storage Integration

[Source: architecture/7-apis-externes.md#7.5]

**OVH Object Storage Details:**
- **Purpose:** Store user profile photos
- **Documentation:** https://docs.ovh.com/gb/en/storage/object-storage-swift-api/
- **Base URL:** https://s3.{region}.cloud.ovh.net
- **Authentication:** AWS Signature V4 (S3 compatible)
- **Rate Limits:** No limit, pay-per-use
- **Operations:**
  - `PUT /{bucket}/{key}` - Upload image
  - `DELETE /{bucket}/{key}` - Delete image
- **Integration:** Use `league/flysystem-aws-s3-v3` package with Laravel Filesystem

**Configuration Example:**

`config/filesystems.php`:
```php
'disks' => [
    'ovh' => [
        'driver' => 's3',
        'key' => env('OVH_ACCESS_KEY'),
        'secret' => env('OVH_SECRET_KEY'),
        'region' => env('OVH_REGION', 'gra'),
        'bucket' => env('OVH_BUCKET', 'travelconnect-avatars'),
        'endpoint' => env('OVH_ENDPOINT', 'https://s3.gra.cloud.ovh.net'),
        'visibility' => 'public',
        'url' => env('OVH_URL'),
    ],
],
```

`.env`:

### Image Processing Requirements

[Source: Acceptance Criteria #6]

**Image Specifications:**
- **Target Size:** 400x400px (square)
- **Format:** JPEG preferred, PNG supported
- **Quality:** 80% compression for JPEG
- **Max Upload Size:** 5MB
- **Processing Steps:**
  1. Validate file type (JPEG/PNG only)
  2. Resize to 400x400px maintaining aspect ratio
  3. Crop to square (center crop)
  4. Compress to 80% quality
  5. Convert to JPEG if PNG
  6. Upload to OVH storage
  7. Delete old avatar if exists

**Backend Implementation:**

```php
use Intervention\Image\Facades\Image;
use Illuminate\Support\Facades\Storage;

public function uploadAvatar(UploadedFile $file, User $user): string
{
    // Resize and process image
    $image = Image::make($file)
        ->fit(400, 400) // Resize and crop to 400x400
        ->encode('jpg', 80); // Convert to JPEG with 80% quality

    // Generate filename
    $filename = "avatars/{$user->id}_" . time() . '.jpg';

    // Delete old avatar if exists
    if ($user->avatar_url) {
        $oldKey = parse_url($user->avatar_url, PHP_URL_PATH);
        Storage::disk('ovh')->delete($oldKey);
    }

    // Upload to OVH
    Storage::disk('ovh')->put($filename, $image->stream(), 'public');

    // Get public URL
    $avatarUrl = Storage::disk('ovh')->url($filename);

    // Update user
    $user->update(['avatar_url' => $avatarUrl]);

    return $avatarUrl;
}
```

**Frontend Implementation:**

```dart
import 'package:image/image.dart' as img;

Future<File> resizeImage(File imageFile) async {
  // Read image
  final bytes = await imageFile.readAsBytes();
  img.Image? image = img.decodeImage(bytes);

  if (image == null) {
    throw Exception('Unable to decode image');
  }

  // Resize to 400x400
  img.Image resized = img.copyResize(
    image,
    width: 400,
    height: 400,
    interpolation: img.Interpolation.average,
  );

  // Encode as JPEG with 80% quality
  final resizedBytes = img.encodeJpg(resized, quality: 80);

  // Save to temporary file
  final tempDir = await getTemporaryDirectory();
  final tempFile = File('${tempDir.path}/avatar_${DateTime.now().millisecondsSinceEpoch}.jpg');
  await tempFile.writeAsBytes(resizedBytes);

  return tempFile;
}
```

   - Submit all data to PUT `/api/user/profile`
   - Backend sets `is_new` to false
   - Navigate to MapPage
   - Show welcome message

**Navigation Logic:**

```dart
// In app_router.dart
redirect: (context, state) {
  final authState = context.read<AuthBloc>().state;

  if (authState is Authenticated) {
    final isNew = authState.user.isNew;

    if (isNew && state.matchedLocation != '/onboarding') {
      return '/onboarding';
    }

    if (!isNew && state.matchedLocation == '/onboarding') {
      return '/map';
    }
  }

  return null;
}
```

### Security Considerations

[Source: architecture/15-sécurité-et-performance.md]

**Profile Security:**
- Only authenticated users can access profile endpoints
- Users can only view/edit their own profile
- Validate all input data server-side
- Sanitize bio text to prevent XSS attacks
- Rate limit avatar uploads (max 10 per hour)
- Validate image file type by content, not just extension
- Limit avatar file size to prevent DoS attacks

**Storage Security:**
- Store avatars in public bucket (read-only public access)
- Use signed URLs for uploads (if needed)
- Implement file name randomization to prevent overwrites
- Delete old avatars when new ones are uploaded
- Scan uploaded files for malware (optional, recommended)
