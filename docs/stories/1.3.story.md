### Apple Sign-In Integration

[Source: architecture/7-apis-externes.md#7.2]

**API Details:**
- **Base URL:** https://appleid.apple.com
- **Authentication:** Identity Token JWT
- **Rate Limits:** No documented limits
- **Documentation:** https://developer.apple.com/sign-in-with-apple

**Endpoints Used:**
- `POST /auth/token` - Validate identity token
- `GET /auth/keys` - Public keys for JWT validation

**Integration Notes:**
- Mandatory for iOS apps that use other social login providers (App Store requirement)
- Supports "Hide My Email" feature - creates relay email (xxx@privaterelay.appleid.com)
- User information (name, email) provided only on first authentication
- Must use Laravel Socialite with Apple provider for backend validation
- Identity token is JWT signed by Apple - must verify signature

### API Endpoint Specification

[Source: architecture/5-spécification-api-rest.md#5.3.2]

**Endpoint:** `POST /api/auth/apple`

**Request Body:**
```json
{
  "identity_token": "apple_identity_token_jwt",
  "authorization_code": "apple_auth_code",
  "full_name": {
    "given_name": "John",
    "family_name": "Doe"
  }
}
```

**Validation Rules:**
- `identity_token`: required, string
- `authorization_code`: required, string
- `full_name`: nullable, object
- `full_name.given_name`: nullable, string, max:50
- `full_name.family_name`: nullable, string, max:50

**Success Response (200 OK):**
```json
{
  "user": {
    "id": 1,
    "email": "abc123@privaterelay.appleid.com",
    "name": "John Doe",
    "avatar_url": null,
    "user_type": "traveler",
    "trust_score": 0.00,
    "is_new": true
  },
  "token": "1|sanctum_token_here",
  "is_new_user": true
}
```

**Error Responses:**
- `401 Unauthorized` - Invalid Apple identity token
- `403 Forbidden` - User is banned
- `422 Validation Error` - Missing or invalid fields
- `500 Server Error` - Internal server error

**Error Format:**
```json
{
  "error": {
    "code": "INVALID_APPLE_TOKEN",
    "message": "Le token Apple est invalide",
    "timestamp": "2026-01-31T10:00:00Z"
  }
}
```

### Backend AuthService Implementation

[Source: architecture/11-architecture-backend-laravel.md#11.4]

**File Location:** `app/Services/AuthService.php`

**Key Methods:**

```php
public function authenticateWithApple(
    string $identityToken,
    string $authorizationCode,
    ?array $fullName = null
): array {
    // 1. Use Socialite to validate Apple identity token
    $appleUser = Socialite::driver('apple')
        ->stateless()
        ->userFromToken($identityToken);

    // 2. Process user name
    $name = 'Utilisateur';
    if ($fullName) {
        $givenName = $fullName['given_name'] ?? '';
        $familyName = $fullName['family_name'] ?? '';
        $name = trim("{$givenName} {$familyName}");
        if (empty($name)) {
            $name = 'Utilisateur';
        }
    }

    // 3. Find or create user
    return $this->findOrCreateUser(
        provider: 'apple',
        providerId: $appleUser->getId(),
        email: $appleUser->getEmail(),
        name: $name,
        avatarUrl: null // Apple doesn't provide profile pictures
    );
}
```

**Important Notes:**
- Apple returns user information (name, email) ONLY on first authentication
- Subsequent authentications return only the unique user ID (sub)
- Backend must store name on first auth and reuse on subsequent auths
- "Hide My Email" creates relay addresses like abc123@privaterelay.appleid.com
- These relay addresses must be stored and treated as real emails
- Avatar URL is always null for Apple users (no profile photo provided)

### Database Schema

[Source: architecture/9-schéma-de-base-de-données.md]

**Users Table Fields Required:**
- `id` - BIGINT UNSIGNED PRIMARY KEY
- `email` - VARCHAR(255) UNIQUE NOT NULL (supports relay emails)
- `name` - VARCHAR(100) NOT NULL (defaults to "Utilisateur")
- `avatar_url` - VARCHAR(500) NULL (always null for Apple users)
- `provider` - ENUM('google', 'apple') NOT NULL
- `provider_id` - VARCHAR(255) NOT NULL (Apple user ID / sub)
- `user_type` - ENUM('traveler', 'local_supporter') DEFAULT 'traveler'
- `trust_score` - DECIMAL(3,2) DEFAULT 0.00
- `is_new` - BOOLEAN DEFAULT TRUE
- `is_banned` - BOOLEAN DEFAULT FALSE
- `created_at`, `updated_at` - TIMESTAMP

**Indexes:**
- UNIQUE INDEX on (provider, provider_id)
- INDEX on email

**Notes:**
- Email field must support relay email format (up to 255 characters)
- provider_id stores Apple's unique user identifier
- Same user structure as Google auth for consistency

### Security Considerations

[Source: architecture/15-sécurité-et-performance.md]

**Critical Security Rules:**
1. **NEVER** validate Apple tokens client-side only - always validate server-side
2. **ALWAYS** verify identity token JWT signature with Apple public keys
3. **ALWAYS** validate token expiration timestamp
4. **NEVER** trust client-provided user data without token validation
5. **STORE** tokens in secure storage (flutter_secure_storage), never SharedPreferences
6. **PROTECT** Apple private key (.p8 file) - never commit to repository
7. **USE** environment variables for sensitive Apple credentials

**Apple-Specific Security:**
- Identity token is a JWT signed by Apple - verify signature before trusting
- Fetch Apple's public keys from https://appleid.apple.com/auth/keys
- Verify token audience matches your Service ID
- Check token issuer is "https://appleid.apple.com"
- Validate token is not expired (exp claim)

### Hide My Email Feature

**What is it:**
- Apple privacy feature allowing users to hide their real email
- Creates a unique relay address (format: xxxxx@privaterelay.appleid.com)
- Emails to relay address are forwarded to user's real email
- User can disable relay at any time

**Backend Handling:**
- Store relay email address as the user's email in database
- Send notifications/emails to the relay address
- Apple handles forwarding to real email
- Cannot send emails FROM the relay address
- If user disables relay, emails will bounce

**Frontend Handling:**
- Display the relay email in user profile
- User sees their relay email, not real email
- No special handling needed - treat as normal email address

**Best Practices:**
- Always store the email provided by Apple (real or relay)
- Don't try to "detect" or "validate" relay addresses differently
- Treat relay addresses as valid, permanent email addresses
- Document to users that they're using a relay email
