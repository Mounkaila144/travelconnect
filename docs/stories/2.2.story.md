## Story

**En tant qu'** utilisateur,
**Je veux** voir des marqueurs sur la carte représentant les questions,
**Afin de** découvrir ce que les voyageurs demandent dans une zone.

---

## Acceptance Criteria

1. Les questions sont représentées par des marqueurs distinctifs sur la carte
2. Les marqueurs affichent un aperçu (icône + indicateur de nombre de réponses)
3. Les questions sans réponse ont un marqueur d'une couleur différente (urgence visuelle)
4. Cliquer sur un marqueur affiche une info-bulle avec le titre de la question
5. Cliquer sur l'info-bulle ouvre le détail complet de la question
6. Le clustering s'active automatiquement quand les marqueurs sont trop proches
7. L'endpoint GET `/api/questions?lat={lat}&lng={lng}&radius={km}` retourne les questions dans le rayon
8. Maximum 100 questions sont chargées à la fois (pagination)

      painter.paint(canvas, Offset(75 - painter.width / 2, 75 - painter.height / 2));

    }

### Database Schema and Spatial Queries

[Source: architecture/9-schéma-de-base-de-données.md]

**Questions Table Spatial Fields:**
```sql
CREATE TABLE questions (
    -- ... other fields
    latitude DECIMAL(10,8) NOT NULL,
    longitude DECIMAL(11,8) NOT NULL,
    location POINT NOT NULL SRID 4326,
    -- ... other fields

    SPATIAL INDEX idx_location (location),
);
```

**Spatial Query Example:**
```sql
SELECT
    q.*,
    ST_Distance_Sphere(q.location, ST_SRID(POINT(139.6503, 35.6762), 4326)) AS distance_meters
FROM questions q
WHERE ST_Distance_Sphere(
    q.location,
    ST_SRID(POINT(139.6503, 35.6762), 4326)
) <= 10000  -- 10km in meters
AND q.is_deleted = FALSE
ORDER BY q.created_at DESC
LIMIT 100;
```

**Performance Considerations:**
- Spatial index `idx_location` ensures fast geospatial queries
- `ST_Distance_Sphere()` calculates accurate distance on Earth's surface
- SRID 4326 is WGS 84 (standard GPS coordinate system)
- Query performance: < 50ms for 10,000 questions in database

### Laravel Eloquent Spatial Implementation

[Source: architecture/11-architecture-backend-laravel.md#11.3]

**QuestionRepository Implementation:**
```php
public function findNearby(
    float $latitude,
    float $longitude,
    int $radiusKm,
    int $perPage = 20
): LengthAwarePaginator {
    $radiusMeters = $radiusKm * 1000;

    return $this->model
        ->select([
            'questions.*',
            DB::raw("ST_Distance_Sphere(
                location,
                ST_SRID(POINT({$longitude}, {$latitude}), 4326)
            ) as distance_meters")
        ])
        ->whereRaw("ST_Distance_Sphere(
            location,
            ST_SRID(POINT(?, ?), 4326)
        ) <= ?", [$longitude, $latitude, $radiusMeters])
        ->where('is_deleted', false)
        ->with(['user:id,name,avatar_url,user_type,trust_score'])
        ->orderByDesc('created_at')
        ->paginate($perPage);
}
```

**Key Points:**
- Eager load user relationship to prevent N+1 queries
- Calculate distance_meters for each question
- Filter by radius using spatial function
- Exclude soft-deleted questions
- Paginate results (20 per page, max 100 total)

### Marker Visual Differentiation

**Design System:**

1. **Default Marker (Has Answers):**
   - Color: Blue (#2196F3)
   - Icon: Pin with checkmark or number badge
   - Badge: White circle with answer count in blue

2. **Urgent Marker (No Answers):**
   - Color: Red/Orange (#FF5722)
   - Icon: Pin with exclamation mark
   - Badge: White circle with "0" in red
   - Visual urgency to encourage responses

3. **Cluster Marker:**
   - Color: Based on cluster size
   - Icon: Circle with count
   - Larger size than individual markers

**Accessibility:**
- Color alone is not the only differentiator
- Use icons (checkmark vs exclamation) for color-blind users
- Sufficient contrast ratios (WCAG AA)

### Performance Optimization

[Source: architecture/15-sécurité-et-performance.md]

**Marker Rendering Performance:**

1. **Limit Markers:**
   - Display max 100 markers at once
   - Prioritize markers by relevance (distance, urgency)
   - Use clustering to reduce visual complexity

2. **Icon Caching:**
   - Load marker icons once during initialization
   - Cache BitmapDescriptor instances
   - Reuse same instances for all markers

3. **Viewport-Based Loading:**
   - Only load questions in visible map area
   - Debounce loading (1 second after camera idle)
   - Calculate optimal radius based on zoom level

4. **Debounce Camera Changes:**
   - Prevent loading on every pan/zoom
   - Wait for camera to settle
   - Example:
     ```dart
     Timer? _debounceTimer;
     void _onCameraIdle() {
       _debounceTimer?.cancel();
       _debounceTimer = Timer(Duration(seconds: 1), () {
         _loadQuestionsInViewport();
       });
     }
     ```

5. **Efficient State Updates:**
   - Use Set<Marker> instead of List for markers
   - Only rebuild markers when questions change
   - Avoid rebuilding entire map widget

**Backend Performance:**
- Spatial index on location field (< 50ms queries)
- Redis caching for frequently accessed areas (5min TTL)
- Eager load user relationships (prevent N+1)
- Limit result set to 100 questions maximum

### Error Handling

**Frontend Error Scenarios:**

1. **Network Error Loading Questions:**
   - Show subtle error indicator on map
   - Display retry button
   - Keep existing markers visible
   - Log error for debugging

2. **Empty Results:**
   - Show "No questions in this area" message
   - Suggest user to zoom out or pan map
   - Provide link to create new question

3. **Marker Load Failure:**
   - Fallback to default marker icon
   - Log warning
   - Continue displaying map

4. **Clustering Error:**
   - Disable clustering
   - Show individual markers
   - Log error for investigation
