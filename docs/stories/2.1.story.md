## Story

**En tant qu'** utilisateur,
**Je veux** voir une carte interactive de ma zone,
**Afin de** visualiser les questions posées autour de moi.

---

## Acceptance Criteria

1. La carte Google Maps s'affiche en plein écran comme vue principale
2. La carte se centre sur la position actuelle de l'utilisateur au chargement
3. L'utilisateur peut zoomer, dézoomer et naviguer sur la carte
4. Un bouton "Ma position" permet de recentrer sur la localisation actuelle
5. La permission de géolocalisation est demandée avec une explication claire
6. Si la permission est refusée, la carte affiche une position par défaut (Tokyo)
7. Le chargement de la carte prend moins de 3 secondes sur 4G

### Geolocation Permissions Strategy

**Android Permissions:**
```xml
<manifest>
    <!-- Always include both permissions -->
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
    <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />

    <!-- Optional: Background location (not needed for this story) -->
    <!-- <uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" /> -->
</manifest>
```

**Android Runtime Permission Flow:**
1. Check permission status with `permission_handler`
2. If not granted, show rationale dialog explaining why we need location
3. Request permission using `Permission.location.request()`
4. Handle result: granted, denied, or permanently denied
5. If permanently denied, show dialog with option to open Settings

**iOS Permissions:**
```xml
<key>NSLocationWhenInUseUsageDescription</key>
<string>TravelConnect a besoin de votre position pour afficher les questions autour de vous</string>

<!-- Optional: Always authorization (not needed) -->
<!-- <key>NSLocationAlwaysAndWhenInUseUsageDescription</key> -->
```

**iOS Permission Flow:**
1. System automatically shows permission dialog when location is first requested
2. User can choose: Allow While Using App, Allow Once, or Don't Allow
3. iOS 14+: User can choose Precise or Approximate location
4. If approximate, can request temporary full accuracy with `requestTemporaryFullAccuracyAuthorization`

### Frontend Architecture Pattern

[Source: architecture/10-architecture-frontend-flutter.md]

**Clean Architecture Layers:**

1. **Data Layer:**
   - `LocationLocalDataSource` - Geolocator and permission_handler wrapper
   - `LocationRepositoryImpl` - Implements domain repository
   - `MapPositionModel` - Data model with fromJson/toJson

2. **Domain Layer:**
   - `MapPosition` entity - Core location model (lat, lng, zoom)
   - `LocationRepository` interface - Abstract repository
   - `GetCurrentLocation` use case - Get user's current position
   - `CheckLocationPermission` use case - Check permission status
   - `RequestLocationPermission` use case - Request permission

3. **Presentation Layer:**
   - `MapBloc` - State management for map and location
   - `MapPage` - Main map screen
   - `MapView` - GoogleMap widget wrapper
   - `MyLocationButton` - Custom FAB for recentering

**State Management Pattern:**
```dart
// Events
sealed class MapEvent {}
class InitializeMap extends MapEvent {}
class RequestLocationPermission extends MapEvent {}
class GetCurrentLocation extends MapEvent {}
class MoveToMyLocation extends MapEvent {}
class MapMoved extends MapEvent {
  final CameraPosition position;
  MapMoved(this.position);
}

// States
sealed class MapState {}
class MapInitial extends MapState {}
class MapLoading extends MapState {}
class MapLoaded extends MapState {
  final GoogleMapController controller;
  final MapPosition currentPosition;
  final bool hasLocationPermission;
  MapLoaded({
    required this.controller,
    required this.currentPosition,
    required this.hasLocationPermission,
  });
}
class LocationPermissionDenied extends MapState {
  final MapPosition defaultPosition; // Tokyo
  LocationPermissionDenied(this.defaultPosition);
}
class LocationPermissionDeniedPermanently extends MapState {}
class MapError extends MapState {
  final String message;
  MapError(this.message);
}
```

### Geolocator Package Usage

**Package:** `geolocator: ^10.1.0`

**Get Current Location:**
```dart
Future<Position> getCurrentLocation() async {
  try {
    final position = await Geolocator.getCurrentPosition(
      desiredAccuracy: LocationAccuracy.high,
      timeLimit: Duration(seconds: 10),
    );
    return position;
  } on TimeoutException {
    // Location fetch timed out
    throw LocationTimeoutException();
  } on LocationServiceDisabledException {
    // Location services disabled
    throw LocationServiceDisabledException();
  } on PermissionDeniedException {
    // Permission denied
    throw PermissionDeniedException();
  }
}
```

**Check Location Service Status:**
```dart
Future<bool> isLocationServiceEnabled() async {
  return await Geolocator.isLocationServiceEnabled();
}
```

**Location Settings:**
- `LocationAccuracy.high` - Uses GPS (most accurate, battery intensive)
- `LocationAccuracy.medium` - Uses network (balanced)
- `LocationAccuracy.low` - Coarse location (least accurate, battery friendly)

For this story, use `LocationAccuracy.high` for best user experience.

### Performance Optimization

[Source: architecture/15-sécurité-et-performance.md]

**Map Load Time Target: < 3 seconds on 4G**

**Optimization Strategies:**

1. **Lazy Initialization:**
   - Load map controller on demand
   - Defer marker loading until map is ready (Story 2.2)

2. **Tile Caching:**
   - Google Maps SDK automatically caches tiles
   - Configure cache size if needed
   - Preload tiles for expected viewport

3. **Camera Debouncing:**
   - Debounce `onCameraMove` events (300ms)
   - Prevents excessive state updates
   - Example:
     ```dart
     Timer? _debounce;
     void _onCameraMove(CameraPosition position) {
       if (_debounce?.isActive ?? false) _debounce!.cancel();
       _debounce = Timer(const Duration(milliseconds: 300), () {
         context.read<MapBloc>().add(MapMoved(position));
       });
     }
     ```

4. **Lite Mode:**
   - Use lite mode for static map previews
   - Not applicable for interactive map (this story)

5. **Network Optimization:**
   - Load map tiles on WiFi when possible
   - Show cached tiles when offline
   - Reduce tile quality on slow networks

**Performance Monitoring:**
```dart
final stopwatch = Stopwatch()..start();
// Load map
stopwatch.stop();
if (kDebugMode) {
  print('Map loaded in ${stopwatch.elapsedMilliseconds}ms');
}
// Assert < 3000ms in tests
```

### Error Handling Strategy

[Source: architecture/18-stratégie-de-gestion-derreurs.md]

**Location Error Scenarios:**

1. **Permission Denied:**
   - Show SnackBar: "Permission de localisation refusée. Affichage de Tokyo par défaut."
   - Display map with Tokyo location
   - Show info icon explaining how to enable permission

2. **Permission Permanently Denied:**
   - Show dialog with option to open Settings
   - Message: "La permission de localisation est désactivée. Veuillez l'activer dans les paramètres."

3. **Location Service Disabled:**
   - Show dialog: "Le service de localisation est désactivé. Veuillez l'activer pour voir votre position."
   - Provide button to open location settings (Android)

4. **Location Timeout:**
   - Show SnackBar: "Impossible d'obtenir votre position. Veuillez réessayer."
   - Fallback to Tokyo default location
   - Retry button in SnackBar

5. **Network Error (Map Tiles):**
   - Show cached tiles if available
   - Display subtle error indicator
   - Auto-retry when network restored

6. **Map Initialization Failure:**
   - Show error screen with retry button
   - Log error details for debugging
   - Provide fallback to list view (Story 2.4)

### Security Considerations

[Source: architecture/15-sécurité-et-performance.md]

**Google Maps API Key Security:**

1. **Never Commit API Keys:**
   - Store in environment variables
   - Use `.env` files (not committed)
   - Use CI/CD secrets for builds

2. **Restrict API Keys:**
   - Android: Restrict to package SHA-1 fingerprint
   - iOS: Restrict to bundle identifier
   - Backend: Restrict to server IP addresses
   - Set usage quotas to prevent abuse

3. **Separate Keys:**
   - Development key for local testing
   - Production key for release builds
   - Different keys for Android, iOS, Backend

**Location Privacy:**
- Never share user's precise location without consent
- Only request "When In Use" permission (not "Always")
- Don't track location in background
- Clear location data when user logs out
