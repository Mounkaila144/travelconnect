# プロジェクトブリーフ: TravelConnect

---

## 1. エグゼクティブサマリー

**TravelConnect**は、旅行者と目的地を訪れたことがある人や現地に住んでいる人をつなぐコミュニティベースのモバイルアプリケーションです。

**解決する主な問題:** 旅行者、特に海外旅行者は、信頼できる情報の不足、言語の壁、孤立感による不安に直面しています。現在のソリューション（ガイドブック、フォーラム、AI）には、本物の人間とのつながりやリアルタイムのパーソナライズされたアドバイスが欠けています。

**ターゲット市場:** 海外旅行をする日本人旅行者（初期市場）、安全性と本物の体験を求めるすべての旅行者へ拡大予定。

**価値提案:** 「旅の質問に本当の人が答えてくれる唯一のアプリ — 地元の人、駐在員、経験豊富な旅行者が友達のようにあなたをガイドします。」

---

## 2. 問題提起

### 現状と課題

海外旅行者は以下の主要な課題に直面しています：

- **旅行前の不安** — 安全性、交通機関、避けるべきエリア、よくある詐欺についての不確実性
- **言語の壁** — 外国語で正確な情報を得ることの難しさ
- **断片化した情報** — アドバイスがブログ、フォーラム、ガイドブックに散在し、しばしば古くなっていたり一般的すぎたりする
- **一人旅の孤立感** — 人とのつながりの欠如、脆弱さの感覚
- **ストレスフルな決断** — 信頼できる口コミなしに適切なホテル/レストランを選ぶこと（家族向け、女性一人旅、予算など）

### 問題の影響

| 種類 | 影響 |
|------|------|
| **感情面** | ストレス、不安、恐怖によって台無しになる体験 |
| **実用面** | 悪い選択（立地の悪いホテル、観光客向けレストラン、詐欺） |
| **経済面** | 地元情報の不足によるコスト増（タクシー vs 公共交通機関、地元価格） |
| **社会面** | 出会いの機会を逃し、旅がより豊かにならない |

### 既存ソリューションの限界

| ソリューション | 限界 |
|----------------|------|
| Google Maps | 事実情報のみ、パーソナライズされた人間のアドバイスなし |
| TripAdvisor | 偽のレビューが多い、直接的なやり取りなし |
| フォーラム（Reddit等） | 返信が遅い、位置情報なし、匿名 |
| ガイドブック | 静的、一般的、すぐに古くなる |
| ChatGPT/AI | 実体験なし、ハルシネーションの可能性、本物らしさの欠如 |

### 緊急性

COVID後、国際観光が力強く回復しています。日本人旅行者（COVID前は年間1,800万件以上の旅行）は、自信を持って旅行するためのソリューションを積極的に探しています。この市場を獲得する絶好のタイミングです。

## 3. 提案するソリューション

### コアコンセプト

**TravelConnect**は「旅のソーシャルOS」— 旅行者をリアルタイムでつなぐ位置情報ベースのコミュニティプラットフォームです：

- **地元の人々**（住民、駐在員）が日常の専門知識を共有
- **経験豊富な旅行者**がすでにその目的地を訪れた人々
- **他の旅行者**が同じ時期に滞在し、つながりを作る

### キーアプローチ

**「アルゴリズムではなく、人間」** — すべての質問に、過去の貢献に基づく可視化された信頼スコアを持つ本当の人が回答します。

### 独自の差別化要因

| 側面 | TravelConnect | 競合他社 |
|------|---------------|----------|
| **回答** | 人間による、パーソナライズされた、リアルタイム | AIまたは静的なレビュー |
| **位置情報** | 現在地に関連した質問 | 手動検索 |
| **信頼性** | 透明な評価スコア | 匿名または偽のレビュー |
| **コミュニティ** | 実際の出会いが可能 | 限定的なやり取り |
| **コンテキスト** | フィルター（家族、一人旅、女性、予算） | 画一的 |

### なぜ成功するか

1. **深い感情的ニーズ** — 旅の不安は普遍的で、人間による安心感は代替不可能
2. **ネットワーク効果** — 地元の人/旅行者が増えるほど、アプリの価値が高まる
3. **貢献者のモチベーション** — 評価システム + 助ける喜び + 将来の収益化の可能性
4. **タイミング** — 観光の回復 + 一般的なAIソリューションへの疲れ

### プロダクトビジョン

*「TravelConnectがあれば、世界中のどの街にも友達がいるようなもの。」*

## 4. ターゲットユーザー

### 主要セグメント：不安を抱える好奇心旺盛な旅行者

**人口統計プロファイル：**
- 日本人、25〜45歳、都市部（東京、大阪、名古屋）
- 中〜高所得、年1〜3回海外旅行
- デジタルに精通、LINE、Instagram、Google Mapsを日常的に使用

**現在の行動：**
- 旅行前に何時間もリサーチ（ブログ、YouTube、フォーラム）
- アドバイスをNotesやLINEにスクリーンショット
- 旅行経験のある友人に聞くが、限られたネットワーク
- 未知への恐怖から定番コースから外れることを躊躇

**具体的な課題：**
- 「この地区は夜安全かな？」
- 「このレストランは本当に美味しい？それとも観光客向けの罠？」
- 「この交通システムはどう使うの？」
- 「一人旅で寂しい」

**目標：**
- 自信と安心を持って旅行する
- 本物の体験を発見する（観光客向けでない）
- 一人旅でも見守られている感覚
- 時間と予算を最適化

---

### 二次セグメント：ローカルサポーター（貢献者）

**プロファイル：**
- 海外在住の日本人駐在員、または自分の街に情熱を持つ地元の人
- 共有好き、社交的、住んでいる場所への誇り
- すでにフォーラム/SNSで助ける活動をしている

**モチベーション：**
- 認知（可視化された評価スコア）
- 社会的つながり（旅行者との出会い）
- 利他主義（自分が助けられたように助ける）
- 将来の収益化（有料ガイドになる）

---

### 三次セグメント（将来の拡大）

| セグメント | 特徴 | 具体的なニーズ |
|------------|------|----------------|
| **家族** | 子連れの親、綿密な計画 | 子供向けレストラン、安全な活動 |
| **女性一人旅** | 安全性最優先、信頼できるコミュニティ | 安全な地区、女性推奨の宿泊施設 |
| **効率重視の旅行者** | ビジネスマン、限られた時間 | 最適化、時間の無駄なし |
| **バックパッカー** | 低予算、冒険家 | 地元のお得情報、出会い |

## 5. 目標と成功指標

### ビジネス目標

- **OB1:** ローンチ後6ヶ月で月間アクティブユーザー（MAU）10,000人達成
- **OB2:** 10の人気目的地（パリ、ソウル、台北、バンコク、シンガポール、ハワイ、LA、NYC、ロンドン、シドニー）で500人の認証済みローカルサポーターを獲得
- **OB3:** 質問の80%に対して平均回答時間2時間未満を達成
- **OB4:** 最初の12ヶ月でNPS（ネットプロモータースコア）50以上を獲得
- **OB5:** 外部資金調達前にプロダクトマーケットフィットを検証

### ユーザー成功指標

- **不安の軽減:** 70%のユーザーが使用後「より自信を持った」と回答（旅行後アンケート）
- **回答の質:** 平均評価 ≥ 4.2/5
- **本物の発見:** 60%のユーザーがローカルサポーター推奨の場所を訪問
- **人間的つながり:** 30%のユーザーがアプリ経由で意味のある会話を経験
- **リテンション:** 40%のユーザーが次の旅行で再利用

### KPI（重要業績評価指標）

| KPI | 定義 | MVP目標 |
|-----|------|---------|
| **DAU/MAU** | 日次/月次アクティブユーザー比率 | > 20% |
| **質問/日** | 1日あたりの投稿質問数 | > 50 |
| **回答時間** | 最初の回答までの中央値 | < 2時間 |
| **回答率** | 少なくとも1件の回答を受けた質問の割合 | > 85% |
| **平均信頼スコア** | 回答者の平均評価 | > 3.5/5 |
| **ローカル転換率** | アクティブなローカルサポーターになった登録者の割合 | > 5% |
| **7日リテンション** | 登録7日後にアクティブなユーザーの割合 | > 30% |

## 6. MVPスコープ

### 必須機能（Must Have）

| # | 機能 | 説明 | 理由 |
|---|------|------|------|
| 1 | **インタラクティブマップ** | 位置情報付き質問が見えるマップ表示 | 体験の基盤 — 「周りの質問」を見る |
| 2 | **質問投稿** | 現在地または将来の目的地に関連した質問を投稿 | コア機能 — 旅行者の主なニーズ |
| 3 | **回答システム** | テキストで質問にコメント/回答 | 人間的つながりを可能に — アプリの本質 |
| 4 | **シンプルなプロフィール** | 名前、写真、短い自己紹介、バッジ（旅行者/ローカル）、国 | 信頼とアイデンティティを作る |
| 5 | **信頼スコア** | 回答評価に基づく評価 | 主要な差別化要因 — 品質をフィルター |
| 6 | **プッシュ通知** | 新しい回答やエリア内の質問のアラート | エンゲージメントと反応性 |
| 7 | **フィード/フォーラム** | 目的地別の最近の質問リスト | パッシブな発見、マップの代替ナビ |

### MVPスコープ外（V2以降）

- ❌ **プライベートメッセージ（DM）** — モデレーションの複雑さ、V2
- ❌ **フォロー機能** — まずコミュニティ、その後ソーシャル
- ❌ **高度なフィルター**（家族、女性一人旅、予算）— 基本コンセプト検証後
- ❌ **対面での出会い** — 法的/安全リスク、成熟が必要
- ❌ **ローカルサポーターの収益化** — 価値を証明した後
- ❌ **自動多言語対応** — MVPは日本語のみ
- ❌ **オフラインモード** — 技術的複雑さ、V2
- ❌ **予約連携**（ホテル、レストラン）— 将来のパートナーシップ
- ❌ **高度なゲーミフィケーション** — バッジ、レベル、報酬 = V2

### MVP成功基準

MVPは3ヶ月後に以下を達成した場合**成功**とみなします：

| 基準 | 最低閾値 |
|------|----------|
| 投稿された質問 | > 500件 |
| 回答率 | > 70%の質問に1件以上の回答 |
| 回答時間中央値 | < 4時間 |
| 平均回答評価 | ≥ 3.8/5 |
| M1リテンション | > 20%の登録者が30日後もアクティブ |
| 定性フィードバック | > 60%が「友人に勧める」 |

**ピボットシグナル:** 回答率 < 50% または中央値 > 12時間 → ローカルサポーター獲得戦略の見直し

## 8. 技術的考慮事項

### プラットフォーム要件

| 側面 | 要件 |
|------|------|
| **ターゲットプラットフォーム** | iOS + Android（Flutter） |
| **最小iOSバージョン** | iOS 15+ |
| **最小Androidバージョン** | Android 10+（API 29） |
| **Web** | MVPでは非優先 |
| **パフォーマンス** | マップ読み込み < 3秒、APIレスポンス < 500ms |

### 技術スタック

| レイヤー | 技術 | 備考 |
|----------|------|------|
| **モバイル** | **Flutter** | クロスプラットフォーム、リッチUI、良好なパフォーマンス |
| **バックエンド** | **Laravel（PHP）** | 堅牢なフレームワーク、成熟したエコシステム、REST API |
| **データベース** | **MySQL** | MySQL 8+の空間拡張による地理空間クエリ |
| **認証** | **ソーシャルログイン** | Laravel Socialite経由でGoogle、Apple |
| **ホスティング** | **OVH** | ヨーロッパのサーバー、コストパフォーマンス良好 |
| **マップ** | Mapbox または Google Maps SDK | 要決定 |
| **プッシュ通知** | Firebase Cloud Messaging（FCM） | 無料、iOS/Androidで信頼性高い |
| **メディアストレージ** | OVH Object Storage | プロフィール写真、質問の画像 |

### アーキテクチャ考慮事項

| 側面 | 推奨 |
|------|------|
| **リポジトリ構造** | 2つのリポジトリ：`travelconnect-api`（Laravel）+ `travelconnect-app`（Flutter） |
| **API** | Laravel REST API、Swagger/OpenAPIでドキュメント化 |
| **認証** | APIトークン用Laravel Sanctum + OAuth用Socialite |
| **位置情報** | MySQL 8空間関数（ST_Distance、ST_Within） |
| **リアルタイム** | Laravel Broadcasting + PusherまたはSocket.io |
| **セキュリティ** | HTTPS、Laravelバリデーション、レート制限、CSRF |
| **モデレーション** | Laravel管理画面でのモデレーションキュー |

### 主要な前提条件

| # | 前提条件 | 誤りの場合のリスク |
|---|----------|-------------------|
| H1 | 旅行者はAIよりも人間の回答を好む | 差別化要因が無効 |

| H3 | 評価スコアが信頼を生む | 低い採用率 |
